# Dummy Data Execution Order

The SQL scripts in this directory are generated by two python scripts: `generate_dummy_data.py` and `generate_users_dummy_data.py`. 

Due to foreign key constraints and microservice architecture dependencies, you **must** execute the scripts in the following order. Specifically, the **Identity Service** database must be populated first so that the user IDs exist when the other databases try to reference them (as `owner_id`, `customer_id`, `user_id`, etc).

## 1. Identity Database (`identity_db`)
First, populate the users and roles. This ensures all Restaurant Owners, Customers, and Delivery Riders have valid login credentials and UUIDs.
1. `dummy_identity_data.sql`
2. `dummy_riders_customers_identity.sql`

## 2. Restaurant Database (`restaurant_db`)
Once the restaurant owners are seeded in the identity DB, you can populate the restaurants, outlets, and menu items.

**Important Note regarding PostGIS:**
The `dummy_data.sql` script contains `ST_SetSRID` commands which require the `postgis` extension. Before running this script, ensure the extension is enabled in the database, either by letting the `restaurant-service` startup completely first (which initializes it) or by manually running `CREATE EXTENSION IF NOT EXISTS postgis;`. If this is not done, the transaction will fail and no restaurants will be inserted.

3. `dummy_data.sql`

## 3. Customer Database (`food_delivery` / `customer_db`)
Once the customer login profiles are created in the identity DB, populate their profiles and saved addresses.
4. `dummy_customers.sql`
5. `dummy_customer_data.sql`

## 4. Delivery Database (`delivery_db`)
Once the delivery rider login profiles are created in the identity DB, populate their delivery executive profiles and statuses.
6. `dummy_riders.sql`
7. `dummy_delivery_data.sql`

*(Note: The delivery riders' real-time locations are typically stored in a Redis Geo-Index `drivers:geo:BLR`, which needs to be populated via `GEOADD` commands if testing live map tracking).*
